# Settings / Display 手机 UI 里程碑

日期：2026-08-23（2026-08-24 补充映射式 Surface 回归）

本里程碑只改进 Bndroid 自有 Shell/App UI 与本地预览启动的构建闭包。它没有增加
syscall、wire ABI、handle、capability、存储写权限或设备权限，也没有下载 AOSP、
修改 Android SDK、连接或操作实体设备。

## 已验证界面

- QEMU scanout 是物理 `720×1600`、20:9；UI 使用 `360×800 dp` 设计网格并精确
  2 倍光栅化。这里的 “dp” 是 Bndroid UI 比例，不声称真实面板 DPI。
- Settings 首页现在按 Personalization、Connections、This phone、System 分组，
  保留 Apps 与 About phone 的原有物理点击区域。
- Display & appearance 是真实子页面，包含会话级 dark mode、accent color 和五档
  software dimming；返回动作回到 Settings。
- 尚不存在的能力不伪装成可用开关：网络显示 `Unavailable in QEMU`，外设显示
  `No device transport`，声音显示 `Not implemented`。
- Display 页面明确显示 `Software surface only`，不声称物理背光、HDR、刷新率或
  显示面板控制。

## 受保护栈修复

第一轮 QEMU 点击 Settings 暴露了 host 光栅测试无法发现的 EL0 guard-page fault：
单体 `render_settings` 在 release AArch64 中一次申请约 `0x20a0`（8352）字节栈，
叠加调用链后超过普通 App 的四页（16 KiB）用户栈。

修复没有扩大栈或放宽保护页，而是把 Settings 和 Display 拆成顺序执行、
`#[inline(never)]` 的 UI 组件，并让只读渲染路径借用 `MobileModel`。修复后 release
AArch64 的 `render_settings` 主帧为 `0x80`（128）字节，最大页面子组件帧为
`0x970`（2416）字节；QEMU 随后完整打开 Settings 和 Display，未再出现用户态
fault。

同时补全 `androidbox_runtime` 对新增 APK/ZIP、manifest catalog 和 launcher-icon
拒绝原因的封闭映射，使默认 `mobile-ui-runtime,androidbox-dex0` 启动构建组合重新
通过 AArch64 check。该修复只恢复拒绝原因归类，不扩大 APK 接受范围。

## 2026-08-24 Surface 双缓冲回归

后续实现没有改变 Settings/Display 的 UI 语义，而是把纯 mobile UI 与有界 DEX0
profile 的完整 720×1600 backing 改为 Launcher/App 各两个映射槽：producer RW、
SurfaceServer RO。mobile `BufferPresent` 当前为 v6，精确选择 client slot，以
`Present/Discard` 区分可见提交与显式释放，并在固定 64-byte wire 内携带最多两个
规范化、非重叠 Damage region；decoder 保留 v5 单矩形兼容。
页面切换采用深度 2 的 async
one-ahead transaction；QEMU 实际观察到 `peak_queued=2`、
`peak_in_flight=2` 和 dual publication。启动为 `write_calls=0`、
`maps=8/8`、`queues=5/5`、`acquires=5/5`、`releases=5`、
`mapped_presents=1`，其中四次启动 Discard 不取得 frame grant。

同一后续回归还把 mobile SurfaceServer 接到共用软件帧钟：100 Hz logical timer
以 divider 2 提供 nominal 50 Hz grant，每次有效提交恰好消耗一个连续 epoch，Discard
或其他取消帧不消耗机会。最新纯 mobile QEMU 的 20 次 accepted commit 对应 20 次 acquire；启动
标记为 `timer_pacing=1`，同时明确保持 `fps_claim=0` 与
`hardware_vsync_claim=0`。这不改变 Settings 像素或控件语义，也不代表实测 50 FPS。

最新 v6 回归为每个槽保留自己的 model baseline，并把已确认/等待确认的可见 scene
baseline 分开；首帧、焦点 generation 变化和 Discard 强制 Full。当前只将按压反馈
按固定控件、滚动页裁剪、通知位移或动态 Android Button 的组件矩形规划，还覆盖
status/Home/lock/shade 时钟、Phone 的号码区 + 按键、Calculator 的结果区 + 按键；
producer 光栅、内核逐区域复制与 compositor damage 使用同一 region set，目标切换
保留两个独立区域，未证明状态回退 Full。纯 mobile 与 DEX0 QEMU 各观察到 4 次确实
改变 scene digest 的 Damage commit；纯 mobile 的最小/最大可见面积为
`32,300/474,240`，DEX0 为 `40,800/89,856`。Settings 页面与主题切换仍按安全规则
回退 Full。

这轮 DEX0 另行暴露的是 AndroidBox 深解析调用链，而不是 Settings 渲染器回归。
非 storage、非 interactive 的 DEX0/安装 profile 用户栈因此从四页增加到八页，
上下 guard page 仍保留；纯 mobile UI 的四页栈和本文件前述 Settings 组件修复
保持不变。完整内存布局、权限、
门禁和边界见 [`MOBILE_MAPPED_BUFFERQUEUE.md`](MOBILE_MAPPED_BUFFERQUEUE.md)。

## 尚未完成

Settings 仍只是第一个可用切片。Sound、Network、Connected devices、Storage、
Privacy、Security、屏幕阅读器/语义无障碍与 System update 仍需对应系统服务后才能
成为可操作页面。AndroidBox 当前仍是受限 APK/DEX/资源子集，不是 ART、Bionic、
Binder、完整 Framework 或一般 Android App 兼容。
