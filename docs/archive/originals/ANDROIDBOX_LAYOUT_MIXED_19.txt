# AndroidBox Layout Mixed-19（ABI 69）

## 结论

opt-in profile `androidbox-layout-mixed19` 是 ABI68
`androidbox-layout-size18` 的 child。两份由本机 Android 36 SDK、AAPT2 和 D8
离线构建、并由仓库测试证书签名的真实 APK，现在可以在一个横向
`LinearLayout` 中同时使用：

```text
固定子项：android:layout_width="132dp"，layout_weight=0
权重子项：android:layout_width="0dp"，android:layout_weight="1"
```

固定宽度、权重、精确高度和逐边 margin/padding 从 AAPT2 二进制 XML 经过严格
解析器、独立 AndroidApp EL0 worker、定长进程协议与可信 App scene model，进入
720×1600、20:9 UI 的同一套布局、光栅、按压反馈和点击命中。ABI68 的两个纯权重
Button、ABI67 的逐边间距以及更早 profile 均保持隔离兼容。

本里程碑没有下载 AOSP、没有修改 Android SDK、没有让 QEMU 联网，也没有连接或
操作实体设备。门禁启动的三个 QEMU 实例均在取证完成后正常终止。

## 严格接纳范围

ABI69 只扩展横向 `LinearLayout` 的直接子项组合。每个直接子项必须二选一：

- `Button + width=Exact(Ndp) + weight=0`；或
- `Button + width=0dp + weight=1..=8`。

`wrap_content` 子项、`Exact + weight`、横向 `TextView`、零权重 `0dp`、未知或
重复属性全部 fail closed。精确尺寸仍只接受 AAPT2 `TYPE_DIMENSION` 的正整数
`1..=255dp`；权重仍只接受 canonical 整数 `1..=8`。所有加减乘除均使用 checked
arithmetic，固定外宽、权重子项 margin 或累计权重无法放入父矩形时不产生布局。

布局只维护一个几何真相：同一个最终 rectangle 同时供光栅、语义文本适配、按压
反馈和 hit-test 使用。Host test 还要求两个完整按钮标签都能在内容宽度内显示，禁止
通过裁字让几何测试“看起来通过”。

## 剩余空间算法与最终几何

横向父项的可分配宽度定义为：

```text
distributable = parent_inner_width
              - sum(fixed_content_width + fixed_left/right_margin)
              - sum(weighted_left/right_margin)
```

权重子项按累计整数权重分配 `distributable`，避免逐项取整留下不可归属像素。固定
子项可以位于权重子项前后；前序固定外宽、前序权重宽和前序 margin 共同决定起点。

真实 fixture 使用：

```text
title width       = 240dp
row height        = 120dp
fixed Button      = width 132dp / height 64dp / weight 0
weighted Button   = width 0dp / height 56dp / weight 1
row padding LTRB  = 6/4/2/8dp
button margins    = 2/1/4/3dp + 6/5/2/1dp
```

最终几何：

```text
title logical       = 34/216/240/40
status logical      = 34/260/292/40
row logical         = 34/304/292/120
row inner           = 40/308/284/108
fixed logical       = 42/309/132/64
weighted logical    = 184/313/138/56

fixed physical      = 84/618/264/128
weighted physical   = 368/626/276/112
```

物理点 `(358,682)` 位于两个内容矩形之间的 margin gap 且不命中；QEMU 使用
`(216,682)` 与 `(506,682)` 分别触发两个真实 APK callback Button。

## ABI 与 AndroidApp 协议

系统 ABI 提升为 69。ABI69 没有增加 syscall、wire 字段或权限，因此 AndroidApp
协议保持 `BNDAPC14` v14，scene descriptor 保持 v5、24 bytes。已有字段足以表达：

```text
layout_width  = Exact / Zero
layout_weight = 0 / 1..8
exact_width   = 132 / 0
margin LTRB   = four bounded dp values
```

六节点 scene 继续使用单 outstanding pull transcript：

```text
Ready(0)
Open(1) -> SceneOpened(node_count=6)
DescribeNode(2..7) -> Node(v5)/TextChunk
Click(8) -> Updated/TextChunk
Click(9) -> Updated/TextChunk
Close(10) -> Closed
```

parser、init admission、AndroidApp worker、App scene model、UI renderer 与 kernel
tracer 都独立复验 mixed 约束。kernel 的最终 transcript 要求节点 4 为
`Exact(132dp), weight=0`，节点 5 为 `Zero, weight=1`，并继续绑定尺寸、逐边
间距、两个 callback ID、动态 StringBuilder 文本和最终 revision。

## AOSP 边界与仍未完成

ABI69 证明的是两个真实、仓库控制的 SDK APK 在受限
`LinearLayout/TextView/Button` 子集中的 fixed+weighted 横向布局。它不是 ART、
Dalvik、ActivityThread、Binder、Bionic、JNI、native library、完整 Android
Framework/system services、一般 APK 或真机兼容证明。

继续扩展有界布局解析不需要 AOSP。进入通用 Android App 路线时，仍应按
`TODO.md` 先确定 Android API/AOSP 基线、许可证、构建资源和 Bndroid 适配边界，
取得用户明确授权后再获取外部组件。

当前仍缺少通用 ViewGroup、vertical weight、start/end 与 RTL、gravity、滚动、
RecyclerView、Compose、主题和 qualifier 布局、完整 PackageManager/权限、网络和
多媒体 bridge、硬件 BSP、GPU、Wi-Fi、基带、摄像头、音频、传感器及实体触控，
因此系统仍不能宣称为可日用真机。
