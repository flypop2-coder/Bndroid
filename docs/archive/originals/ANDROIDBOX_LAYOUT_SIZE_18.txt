# AndroidBox Layout Size-18（ABI 68）

## 结论

opt-in profile `androidbox-layout-size18` 是 ABI67
`androidbox-layout-directional17` 的 child。两份由本机 Android 36 SDK、
AAPT2 和 D8 9.0.3-dev 离线构建、并由仓库测试证书签名的真实 APK，现在可以在
AAPT2 二进制 XML 中使用正整数 `Ndp`：

```text
android:layout_width="Ndp"
android:layout_height="Ndp"
```

尺寸会从 APK 资源严格解析，经独立 AndroidApp EL0 worker、定长进程协议与可信
App scene model，进入 720×1600、20:9 UI 的布局、光栅、按压反馈和点击命中。
`match_parent`、`wrap_content`、横向权重 Button 的 `width=0dp` 以及 ABI67
逐边间距继续兼容。

本轮没有下载 AOSP、没有修改 Android SDK、没有让 QEMU 联网，也没有停止、替换
或操作持续运行的 ABI48 Mac 预览虚拟机。

## 严格支持范围

当前精确尺寸语义有意保持有界：

- 只接受 AAPT2 `TYPE_DIMENSION` 的正整数 dp 编码；
- 精确值限制为 `1..=255dp`；
- `0dp` 只保留给 ABI65 的横向整数权重 Button；
- px、sp、fraction、负数、小数、超过 255dp、未知 unit、未知/重复属性全部
  fail closed；
- descriptor 必须满足 `Exact ⇔ exact_dp != 0`，否则拒绝；
- 精确宽度、精确高度、margin 和 padding 使用 checked arithmetic，越出父矩形
  时拒绝；
- 同一最终 rectangle 同时用于绘制、触控命中与按压反馈。

真实 fixture 使用：

```text
title width       = 240dp
row height        = 120dp
button heights    = 64dp / 56dp
row padding LTRB  = 6/4/2/8dp
button margins    = 2/1/4/3dp + 6/5/2/1dp
```

最终几何：

```text
title logical     = 34/216/240/40
status logical    = 34/260/292/40
row logical       = 34/304/292/120
row inner         = 40/308/284/108
button 1 logical  = 42/309/135/64
button 2 logical  = 187/313/135/56

button 1 physical = 84/618/270/128
button 2 physical = 374/626/270/112
```

Host test 证明物理点 `(360,682)` 位于 gap 且不命中；QEMU 用 `(219,682)` 和
`(509,682)` 分别触发两个真实 APK callback Button。

## BNDAPC14

系统 ABI 提升为 68，AndroidApp 协议升级为 `BNDAPC14` v14，scene node
descriptor 升级为 v5，同时保持 canonical 24 bytes：

```text
byte 12     = layout_weight
byte 13..16 = margin left/top/right/bottom dp
byte 17..20 = padding left/top/right/bottom dp
byte 21     = exact width dp，非 Exact 时必须为 0
byte 22     = exact height dp，非 Exact 时必须为 0
byte 23     = reserved zero
```

六节点场景仍使用单 outstanding pull transcript：

```text
Ready(0)
Open(1) → SceneOpened(node_count=6)
DescribeNode(2..7) → Node(v5)/TextChunk
Click(8) → Updated/TextChunk
Click(9) → Updated/TextChunk
Close(10) → Closed
```

kernel tracer 独立要求节点 1 为 `width=Exact(240dp)`，节点 3 为
`height=Exact(120dp)`，节点 4/5 为 `height=Exact(64/56dp)`，同时复验
ABI67 的逐边 padding/margin 与 ABI65 的 `0dp + weight=1/1`。

## AOSP 边界与仍未完成

ABI68 证明的是两个真实 APK 在受限
`LinearLayout/TextView/Button` 子集中的原生 XML 正整数 dp 尺寸，不是普遍
Android App 兼容。当前继续扩展 APK 解析、布局、framework shim 和进程协议，
不需要下载 AOSP。

若后续目标进入完整 ART/Dalvik、ActivityThread、Binder、Bionic、JNI、native
library 与大规模 Android Framework/system services，应单独评估 AOSP 源码或
预构建 Android runtime/container。两条路线都会显著改变仓库体积、依赖、许可证
审计、内存模型与安全边界，必须先取得用户明确授权。

ABI69 child `androidbox-layout-mixed19` 已在严格 Button-only 横向子集中补上
fixed+weighted 混排，完整证据见 `ANDROIDBOX_LAYOUT_MIXED_19.md`。系统整体仍
缺少通用 ViewGroup、vertical weight、start/end 与 RTL、gravity、滚动、
RecyclerView、Compose、主题与 qualifier 布局选择、完整 PackageManager/权限、
网络 App、任意 APK、硬件 BSP、基带、摄像头、音频、传感器及实体触控驱动，
因此不能宣称为可日用真机系统。
