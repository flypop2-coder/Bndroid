# Bndroid OS

Bndroid OS is an experimental Rust-first operating system that aims to reimplement the Android mobile experience on a non-Linux foundation. Its long-term goal is to become an alternative to Android while running Android applications through AndroidBox.

The repository contains a custom AArch64 kernel, supervised services, storage and UI subsystems, and AndroidBox: a bounded compatibility layer for verified APK ingestion, resource parsing, DEX interpretation, Activity projection, and lifecycle recovery.

The current system is a QEMU research prototype. General-purpose APK compatibility, a complete Android runtime, and production support for physical phones remain future work.

## Current scope

- A custom kernel targeting QEMU `virt` AArch64, with capability-based handles, VMOs, channels, events, and supervised processes.
- Storage, package, graphics, input, and application-data services with recovery tests.
- A 20:9 mobile shell with grouped Settings, Display and Accessibility pages, shared dynamic colors, semantic text sizes, and high-contrast appearance.
- Session-local Overview gestures, verified package icons, lock-screen notification dismissal, and SurfaceServer-owned minute-clock updates.
- Mapped double buffering for the mobile and bounded DEX0 previews; up to two damage regions in the 64-byte mobile `BufferPresent` v6 transaction.
- Region-based rendering and copying for layered AndroidBox, with separate written/presented caches, system-chrome reuse, and measured copy-volume checks.
- ABI 69 fixed-and-weighted horizontal layouts for controlled Android SDK/D8/AAPT2 APK fixtures.

The shared software frame clock provides a nominal 50 Hz grant ceiling. It does not establish hardware VSync, measured FPS, or physical-device performance.

## Quick start

Install the Rust toolchain specified in `rust-toolchain.toml`, QEMU with AArch64 support, and Python 3. Run commands from the repository root:

```sh
./scripts/build-kernel.sh
./scripts/check-qemu-boot.sh
```

For the mobile UI acceptance gate:

```sh
./scripts/check-mobile-ui-runtime.sh
```

AndroidBox SDK fixture gates additionally require the locally installed Android SDK/JDK tools described in their fixture READMEs. Generated builds, screenshots, and logs stay in the ignored `target/` directory.

## Collaboration

External contributions should use a fork and pull request. Keep changes focused and provide reproducible checks, compatibility implications, and known limitations. See [CONTRIBUTING.md](CONTRIBUTING.md), [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), and [SECURITY.md](SECURITY.md).

Bndroid does not accept contributions intended to attack, damage, bypass authorization on, or abuse existing platforms. The main branch should be protected against force-pushes and deletion, with review required for external contributions.
